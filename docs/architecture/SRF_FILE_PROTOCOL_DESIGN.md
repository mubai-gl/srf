## 1. FP-02 入口、索引与模块加载

### 1.1 表达格式与最小索引（F06）

F06已批准 UTF-8 JSON（无BOM、单一对象），源文件 framework/manifest.json、部署 .srf/manifest.json，替代FP-01暂定索引格式；目录规划已统一，不兼容双索引或自动回退。JSON结构可由一般解析工具处理，便于严格类型、路径、引用和依赖检查；Markdown适合正文，不适合复杂机器索引；YAML可读性好但额外语法与解析差异需要限制。依据公开非仓库标准[RFC 8259](https://www.rfc-editor.org/rfc/rfc8259.html)第4/8节（唯一成员名、UTF-8及互操作）与[YAML 1.2.2](https://yaml.org/spec/1.2.2/)相关语法说明（本轮检索结果选段，非全文研读）。JSON不自动安全：严格拒绝重复对象键（包括转义后同名）、非法编码、截断、重复ID/路径、未知字段、错误类型/版本；普通JSON.parse可能吞掉重复键，正式检查必须在对象折叠前识别。禁止注释、尾随逗号、非标准值及执行型表达。限制输入体积、深度和读取次数由真实环境校准，超限不自动截断后继续。框架独立于解析器，不能可靠核验时阻塞依赖操作并交接，不把AI目测当严格解析证据。

| 字段 | 类型/要求 | 权威语义 |
|---|---|---|
| schema_version | 整数，当前候选1，必需 | 索引协议代际，不是框架发布版本；未知版本停止，不按旧协议猜测 |
| entrypoint | 相对路径字符串，必需 | 指向已安装且受信的启动指令源，不能由任意索引改变根 |
| modules | 模块对象数组，必需 | 每项id/path/kind/requires/triggers，唯一ID及路径，未声明不可自动启用 |
| assets | 资源对象数组，必需，可为空 | path/kind/owner；仅实际存在的知识、模板及必要支持资源；owner指向模块ID，不授予权限 |

模块字段：id为稳定标识；path为包内Markdown相对路径；kind为core/adapter/capability/evolution/extension之一；requires为直接必要规范前置ID数组（无重复、允许空）；triggers为非空且唯一的短语义标签数组（小写英文字母起始、字母数字连字符），只辅助定位而非自然语言分类器或执行条件。实际触发/排除、前置、输出/失败等由模块正文契约解释。资产kind候选reference/template/support分别限定knowledge/、templates/、entrypoints/必要支持资源；不得包含执行脚本或外部URL。安装工具、许可及版本/产物证据的必要结构由FP-06补充，而非本轮冻结完整发布协议。

核心、入口、实际模块及已声明资源组成源发布选择入口；不能把目录或未审核文件默认纳入包。最终产物实际清单、版本、摘要、源提交及兼容在FP-06决定，若需扩展字段先经授权修订协议。当前样例不宣称实际包已存在。入口与索引自身不作为运行模块节点，避免索引自依赖。路径相对包根，拒绝绝对路径、空段、点/点点、反斜线、URL、大小写折叠冲突及保留/非法平台路径；允许的ASCII段和真实文件类型、符号链接/重定向必须按实际工具与平台校验，不凭字符串证明解包安全。各模块路径必须符合物理职责，入口路径固定，不能由远端任意值改变可信启动位置。

### 1.2 稳定标识、正文契约与规则定位（F07）

模块ID候选 srf.<语义名>（小写字母起始、字母数字及点/连字符分段），不由路径或版本自动生成；首版14个明确模块，见1.3样例。扩展ID按同一语法且经有效配置及索引准入，必须唯一，不能占用既有ID。规则ID候选 SRF-R-<初始职责命名空间>-<三位序号>，全框架唯一，命名空间用于首次分配而非当前物理归属；不复用退役ID，不因文件移动或条款顺序变化改号。规则拆合或语义破坏性变化须评估消费者/兼容并保留必要迁移定位，不建常规历史文件。普通知识条目不强制编号；重要可追踪约束、公开契约和验收关联需要稳定定位。

正文Markdown固定契约节 `## CONTRACT`：身份/职责及非职责；触发/排除；输入输出/实际前置；权限与执行边界；完成、证据、失败/交接；必要需求/决定/测试关联。索引拥有ID/路径/类型/直接依赖/定位标签的唯一元数据定义，正文不复制这些字段，契约中的身份仅以模块ID定位并与索引一致核验；具体格式候选 `Module: srf.design` 紧随契约标题。规则标题候选 `### SRF-R-GOV-001 | MUST`，紧随自然语言适用范围、约束及例外/覆盖声明（适用时）、证据和必要关联；标题类型是规则性质，不自动赋予效力。五类类型及三个层级仍按J01解释，框架正文中规则属于框架层，项目/任务约束由FP-03定位，不以标题提升其层级。规则引用使用ID及必要版本/适用范围，解析时由已核实索引模块路径与正文精确标题定位，不依赖Markdown渲染器自动锚点。不得以字符串搜索命中代替完整规则及上下文解释。

规则全量二级索引如确有需求由确定性工具从规范正文导出（可在内存生成）；不维护第二份手工ID→路径表。运行按模块/职责/标签缩小搜索，遇已知规则ID可在当前可信范围查找，不能全局搜索其他仓库。PH-07/08结构检查须辨识真实Markdown标题与代码块/引用示例（不把示例当规则）；实际标题重复、失效引用、未知性质或契约身份不符均阻塞依赖规则，其他合法独立分析可继续。复杂语义冲突仍按J01由AI及必要人工审查，不能由正则判断。需求、设计、测试关联在权威正文/测试处按J10保存，反向查询可派生；不要求每条规则建独立文件。

### 1.4 必要依赖闭包及加载准入（F08）

14模块、21条直接必要规范前置边；六核心节点保持原概要13条内部边，GitHub→execution、专业共用→governance、五专业→professional、生命周期→governance 为细化边。映射M01–06各一个核心节点，M05另含GitHub适配，M07含专业共用及五专业，M08生命周期，M09为按有效配置另行准入的可选扩展（不伪造首版已建模块）。将同逻辑单元内部边折叠后，保留概要已批准关系；M09未实体化故其边不计入21条。common对知识来源/证据的使用是语义消费，解释其专业契约仅需governance；执行活动仍消费facts/其他核心，不形成额外规范加载循环。

算法：确认索引来源/版本/路径及完整性 → 严格解析结构及所有声明依赖，拒绝未知节点、重复边、自环、环、核心缺失或依赖可选模块 → 按任务目标与实际能力选择必要模块 → 求直接依赖传递闭包去重，依赖优先确定性拓扑排序（同级可按稳定ID排序，不靠数组顺序决定权限）→ 按版本及权威定位取得完整必要契约与相关规则，核实实际内容/身份/适用性/冲突 → 输出已核实读取引用、缺失及阻塞范围。全图结构有效不等于所有模块都需要读正文；声明结构无效且无法确定影响时阻塞正常运行，不能静默删掉必需边。有效结构内非当前可选能力实际不可用时仅阻塞其依赖活动；若发布清单/运行包完整性要求不成立，先按J35阻塞依赖有效版本的活动。规则来源、覆盖、引用和调用结果不混入必要加载图。核心集合由批准架构/可信产物确定，当前六项不可由索引kind篡改删除；工作流闭包必须恰含六核心。兼容变化需审批及版本迁移，不能以核心节点写死后忽略正式变更。

| 请求解释范围 | 依赖闭包（含请求自身） |
|---|---|
| srf.workflow | 6核心 |
| srf.design | governance、professional、design（3） |
| srf.github | governance、collaboration、facts、execution、github（5） |
| 正常开发+GitHub（workflow+development+github） | 6核心+professional+development+github（9） |
| 正常生命周期（workflow+lifecycle） | 6核心+lifecycle（7） |

解释单个专业/工具规范的闭包不是执行准入；任何正常有副作用任务仍需完整适用核心闭环、事实、有效授权、风险及真实工具前置。正常分析也不能遗漏适用核心约束，不要求全量核心正文每次重读；保留可信且仍适用的完整必要契约及相关条款。扩展只可按有效配置选择，兼容、来源、核心保护、真实能力、权限及测试条件须核实，未启用不加载，不可将扩展设为核心必要前置；具体启用与兼容由FP-03/06决定。

### 1.5 稳定入口与可信自举（F09）

稳定入口为安装后用户实际导入/配置的 .srf/entrypoints/PROJECT_INSTRUCTIONS.md 对应内容，不假定平台会自动读取它。Project根绑定、允许引用及最低安全准入来自用户实际有效配置，入口不能从待核实远端索引获得根信任，也不含通用用户的具体仓库值。入口保留必要自举约束，与core/governance.md权威语义一致；PH-08/09从已确认权威规则生成或逐项核对最小摘录，记录可验证来源及版本，FP-03/06定义实际激活/完整性证据；不允许两份独立可修改治理源。若平台无法核实实际设置，报告限制并要求必要人工证据，而非推断入口已生效。

启动顺序：①核实有效Project配置、对象/允许引用、工具可限定范围及读权限，任何未知停止相关读取；②仅最小限定只读核实仓库身份、实际提交/锁定包及可信入口/索引位置，每次核对参数和返回；③核实可信指定产物、受管文件、配置及入口一致性（J35），严格索引结构及版本，读取必要治理及核心契约；④定位现有权威状态/任务及实际结果，按J36重新判当前授权、按J37确认结果而非复用状态文字；⑤选择任务活动和模块闭包，加载必要上下文，再按正常执行准入开展。初始只读不可写、不能扫描无关范围；身份不符停止，不处理越界数据，不自动回退其他仓库/版本/索引。实际版本、配置、授权和能力变化时重新核实；历史摘要不替代权威状态。PH-08验证试验入口，PH-09形成软件Project正式启动指令，本研发中心入口保持独立。

### 1.6 上下文预算、增量加载与恢复（F10）

沿J09四视角，不新增存储或固定token配额。启动视角先保根、版本和适用核心；任务视角保目标、范围、有效授权、基线、验收、未决/未知；专业视角按活动与闭包取得必要契约、相关完整规则和具体实现/测试；扩展视角仅按价值增加历史、参考、模板与领域扩展。读取前检查实际工具能否提供完整内容/分页/范围；记录或保留可核实引用（对象、版本、路径、模块/规则ID及完整性/范围）。缓存仅用于同一有效基线与相同适用条件，身份/版本/配置/权限/事实变化或返回冲突触发失效；不把跨会话记忆作有效加载。重复前置按ID+已核实版本去重，按稳定引用定位，不能把摘要代替安全关键规则；范围读取须含完整相关条款及其适用条件/例外/依赖，否则补读。工具不能可靠分段或正文截断时，先合法补齐或缩小任务，不能从缺失片段推断规则。

预算压力处理顺序：去重及不相关历史→延迟非必要扩展/参考→分阶段活动、缩小可安全完成范围→保留必要安全、权限、质量与恢复前置；仍不够则停止受影响动作，明确缺失及交接，不删除关键约束以“继续”。未知实际上下文上限/模型费用不虚构数值；PH-08/10试测记录读取文件/段数、重复读取、实际可测token/耗时、遗漏规则及误拒，阈值由正式测试方案决定。合法低风险普通任务不输出完整加载日志；重大风险、冲突、失败和恢复保留最小可定位证据。不能读取必要前置不意味着允许降格执行；任务或配置变化重新选择，不默认全量重载。

### 1.7 兼容、确定性验证及交接（F11）

索引协议schema_version独立于SRF整体版本，仅在必要不兼容协议变化时提高；当前严格模式未知字段/版本停止，未来增加字段须评估旧消费者可否解析，不能仅因“新增字段”宣称兼容。FP-06定义实际公共契约兼容和版本协商；不自动尝试多种解析器、双索引或绕过未知安全字段。索引路径、模块ID/规则ID和公开契约属于拟议稳定定位边界，内部路径迁移须保持ID和更新引用，必要迁移与回滚按J31/32授权，当前无已发布消费者。正式文件校验应检查实际文件存在/类型/完整性、严格解析及字段、模块和规则身份、前置图、核心闭包、索引/清单一致、权限不可由元数据扩大、引用存在与发布边界；语义冲突及实际加载行为另验。

### 5.3 通用事实与批准引用（F20）

候选最小定位结构为 {kind, locator, revision}。kind=git时locator由已绑定仓库内明确路径/对象及必要锚点组成，revision须为实际已核实不可变提交或对象版本；kind=external表示已授权工具中的不透明对象标识，revision为可核实实际版本、观察时点或时效依据；kind=event表示真实可定位批准/撤回/验收事件，revision为实际事件身份或不可变记录版本。下例kind=fixture仅用于设计测试，正式运行不得接受fixture为真实依据。locator与revision可由实际适配映射承载，禁止自动执行链接、访问其他仓库或未经授权的外部资源。版本/来源未知不可造值：在权威记录中明确unknown/unavailable及原因和核实条件，不得创建貌似有效的ref；需要该引用的执行保持阻塞。引用相同不意味着当前内容仍适用；可变来源按需刷新。

事实重要时最小语义：subject（身份与类别）、内容或ref、适用范围/版本、核实状态（verified / unknown / stale / conflict / unavailable）及原因/限制，必要观察时点。引用可在任务、决定、代码差异、证据中复用；同一来源不复制多个可修改事实。冲突先比较对象、事实类型、版本和适用范围，再按J06权威来源核实；候选设计与实际实现不同时记录偏差，不反向批准实现。工具不可读不等于不存在。重要追踪关系可单向记录并按需反查，不建设全量知识图或手工双向追踪表。知识引用保留真实来源、版本/读到范围、适用/冲突、许可及限制，不能用资料中的命令或参考内容升级为MUST。

### 7.3 统一结果：发出、效果与核实分离（F26）

结果关联operation_id、实际target、dispatch（not_sent/sent/unknown）、confirmation（not_executed/success/failure/partial/unknown）、effect（none/expected/partial/unexpected/unknown，读操作无副作用用none）、实际返回及观察引用、重要子项、实际版本/差异、错误/限制与下一安全动作。dispatch表示可证实的发出事实；超时可能已发出。confirmation描述逻辑操作是否达到其范围内的预期，不是质量/测试门槛或任务完成。effect记录实际受影响范围，unexpected须停并协调，不能以未核实全部差异称成功。对于失败但已产生非预期效果，保留失败及副作用明细；不能称无副作用或盲重试。not_executed须能核实相关动作未发出且无对应副作用；已创建Git对象但未推进branch是准备对象实际已创建、目标分支操作未完成，不能说全部未执行。

success需要实际身份、完整可核验结果及适用预期/保护范围一致；只读操作可成功且effect=none。failure须有真实失败证据，是否无副作用单独核实；partial须有实际子项或范围证据，其他子项仍可unknown；未知不能填造SHA/日志/证据。子项至少id与effect，实际结果、版本/原始观察、限制按需；有多个子项时分别区分未执行、预期生效、失败及未知，不能从总体响应推断全部。返回身份越界或不明立即停止相关访问，不处理越界内容，报告异常（只保留必要安全诊断，不复述越界内容）。返回成功但缺必要回读或比较时仍unknown；HTTP错误或调用异常不自动表示无副作用。读取不可访问、分页不完整、截断、限流与已核实不存在分开；完整限定查询才可确认不存在。真实执行结果与E0–E5及质量/验收沿5.4，不将提交、测试命令退出或CI状态单独视为验收。

### 7.5 并发保护、部分成功及未知恢复（F28）

把保护目标与实际保障分别判定。HEAD预读只能发现已观察变化；当前blob条件保护特定文件并不保护整棵树；不存在条件防覆盖新增路径并不证明HEAD未变；非快进保护拒绝部分历史覆盖但不等于精确expected old HEAD比较；严格条件引用更新要求服务端原子比较预期旧引用并更新，只有实际语义及证据足够才能声称具备。即使原子引用更新成功，外部流程/CI/状态记录也不是同一事务。不得使用force:true（包括把force-with-lease作为默认），不得盲目重写历史。若适用任务要求严格分支条件而未验证满足，阻塞副作用并提供交接；独立低风险操作仅在已批准顶层约束及实际对象级条件/风险允许时采用现有接口，明确残余窗口，不能借裁剪降级必需条件。当前正常路径已核实、陈旧blob 409有历史实证；严格分支并发、竞态及部分失败尚未专项验证。

依赖性变更优先一次逻辑提交。能力不足时，只有全部变更已准备、每步实际前置和保护满足、顺序及中间态风险可接受且可恢复才串行；每步更新实际基线、核实结果及已/未执行/未知，任何异常停止相关后续，不把串行当原子。中间不一致不可接受则交接批量环境。准备的Git对象即使未进入branch也可能实际存在，不自动清理或删除对象。

| 情境 | 必要恢复选择 |
|---|---|
| 调用未发出或确证失败且无副作用 | 诊断；当前授权、基线、风险及执行前置重新成立后，才可准备再次执行 |
| 超时/断线/返回不完整 | 保留请求与目标、冻结依赖动作；合法查询实际引用、历史、对象、内容及请求标识，不重放 |
| 预期提交已在目标历史且实际效果核实 | 记录历史成功；若当前HEAD后续变化，重新核实当前适用性，不重新提交旧变更 |
| HEAD不同、历史不完整或只见相同内容 | 不自动判未执行或自己执行成功；核实父子关系、实际差异和其他写入，证据不足保持未知 |
| 部分成功或意外差异 | 逐子项记录预期、实际、未执行及未知；保护他人变化，必要补齐/补偿需适用授权、基线及复验 |
| 状态未保存或同批状态未核实 | J37：按真实结果恢复，不以状态文字推断成功；必要且授权才最小更新 |
| 暂停/撤回、权限丧失或不可核实 | 停止新副作用；仅合法核实已发出的结果，交接已知及未知；无真实取消能力不声称撤销 |

恢复查询也是工具调用，必须在原根范围与实际读权限内；用户整体停止则不开展其他副作用，不能以“恢复”为名自动补偿。历史成功、当前目标满足和当前测试适用是不同事实。回滚是新受控逻辑变更：评估现有后续修改、数据/配置保护及风险，按授权采用安全补偿/revert或其他适用办法，保留历史、不默认强推。当前本Project不得在其他仓库验证上述边界；合成负例不发越界调用。

### 9.2 可信产物身份、清单和摘要（F31）

release.json为严格UTF-8 JSON（沿F06禁止重复键、未知字段/版本、截断、非法编码），候选schema_version=1独立于manifest、config、state及SRF整体SemVer。最小字段：

| 字段 | 语义与验证 |
|---|---|
| schema_version | 必需整数1；未知停止依赖操作 |
| version | 精确整体SemVer；正式1.0.0对应v1.0.0 Tag，受控候选或预发布不得冒充正式版 |
| source_commit | 指定SRF源仓库的实际完整不可变提交标识；由发布环境在绑定仓库核实Tag/提交及实际来源，不能仅信字符串；当前GitHub SHA-1对象使用40位十六进制，其他实际对象格式须经兼容设计 |
| archive | 对象name、size、sha256；名称固定srf.zip，size非负整数字节数且在实际资源限额内，sha256为64位小写十六进制；摘要针对实际完整ZIP原始字节 |
| files | 按规范相对路径排序的唯一对象数组，path、size、sha256；覆盖ZIP中全部且仅实际常规文件，包含manifest、入口、必要许可；每项摘要针对原始文件字节，不做换行、编码或文本重序列化转换 |

release.json自身不在files数组中，ZIP也不含release.json，避免自引用；独立计算描述文件原始字节SHA-256，将用户指定产物的config.framework.artifact_ref具体化为sha256:<64位小写十六进制>，绑定描述文件内容，配置version须与其一致。F12/F14的合成fixture引用仍仅用于设计测试；正式产物不得使用fixture或浮动latest/main。此为F31已批准的artifact_ref正式细化，实际获取位置与身份另由用户确认的合法发布渠道/独立授权环境提供，不将摘要当URL、不自动跨仓库获取。必要发布定位证据包括实际发布仓库、Tag、Release及资产身份、批准的源提交及两资产内容；软件项目不必在线查询研发仓库，允许使用用户从可信渠道交付的描述、ZIP及独立可信摘要/发布依据。不能仅用待核验ZIP、同处可改的配置或描述中的自称版本证明信任，也不能只从描述文件自身重新计算摘要就声称可信。摘要一致证明字节与可信指定值匹配，不证明发布者身份、授权、内容安全或测试通过；可信依据必须独立核实。无法建立来源及绑定时按F14 unknown/blocked停止，不接受“校验和看起来正确”。首版不强制额外签名系统；若实际分发威胁要求签名或更强信任保护，专项评估并取得批准，不宣称SHA替代签名。

验证顺序：合法获取并核实独立可信描述摘要/选择→验证描述字节及严格结构→核实版本与指定源身份的可用可信证明→验证ZIP名称、大小、完整摘要→预检全部档案条目与资源上限→逐文件读取/流式限额验证真实字节及清单相等→严格校验manifest及实际模块/规则/入口/许可→在安全暂存或等价隔离准备区形成可核实计划。安装后保存同一release.json字节，再校验目标实际全部受管文件及描述摘要；描述文件改动视为漂移，不能用其自称内容扩大拥有集合。源选择和生成实际文件清单职责不同，后者只能从实际产物导出，不能手工成为第二份源选择表。清单一致不代表构建可重复：首版要求同一可信产物可重复安装；如果重新构建导致ZIP字节变化，视为新候选产物，必须重新锁定摘要、核实等价或补充验证，不承诺未实现的逐字节可复现构建。
