## 1. 范围、角色与约束

对象是 SRF 自身：规范、由 AI 解释的最小内核、编排、专业能力、工程治理、事实证据、工具适配及独立演进。首版运行环境为 GPT Project/GitHub，核心规范保持工具独立；负责人决定重要方向、授权、验收和发布；AI 在已授权范围内专业主动执行；CI、本地工具、人工等提供真实证据，不把 AI 角色模拟视为独立验证。顶层质量目标为用户简单性与自身迭代性，任何设计不能将内部维护复杂度转嫁给用户。

输入：自然语言目标、需求、反馈、决策、项目事实和工具结果。输出：适度的专业成果、经授权的实际变更、真实证据、可恢复状态及必要的决策请求。无明确写入授权或能力不足时只读分析、降级或交接。禁止将研发中心指令当软件运行指令；SRF 自身首发前仅 main 且不建 PR，不将此项目策略强加给未来软件项目。单仓库白名单是行为约束，不是系统权限隔离。

首版交付边界：可独立部署的版本化运行包、软件 Project 启动指令、最小充分规则/专业知识/模板/适配、兼容及安装升级回滚说明、框架测试及真实证据；不含具体剪辑软件业务研发。独立确定性引擎、自动多 Agent、完整研发平台、全部技术栈和工具适配、组件市场、自动全仓库知识索引及复杂自动化评估平台延后候选；不承诺 V1.0 实现。

## 2. 规格及追踪约定

保留初始需求 52 个稳定 ID，逐项一对一规格化；表内 ID 后三位与依赖栏数字均表示 SRF-REQ- 前缀的需求编号。原始意图及原优先级仍见初始需求对应行；本文件为当前正式需求规格，初始文件作为历史意图来源，不同步维护两套生效需求。全部 52 项需求已批准，尚未实施、验证；主要关联栏为初步语义关联，非已确认模块依赖图或执行顺序。表内为当前正式基线优先级：依据已批准 D01，仅 SRF-REQ-052 由 P1 调整为 P0；P0 是首发必要条件，P1 应在首版实现最小充分能力，任何延期必须由负责人明确批准，且不得豁免 P0 或关键发布保障。验收栏为初步可观察场景，非已执行测试；每个场景须记录输入、基线、环境、证据、预期/实际、结果及限制。正式测试 ID、样本量与阈值按阶段确认。
