# SRF 自身初始需求与建设边界

| 项目 | 内容 |
|---|---|
| 文档编号 | SRF-INIT-03 |
| 状态 | 启动级需求基线；待正式需求规格化与验收设计 |
| 需求对象 | SRF 本身（SRF-REQ），不是使用 SRF 开发的软件（REQ） |

## 1. 需求说明

本文件将已讨论的框架目标、原则和设计方向转换成初始能力需求。它不是最终 SRS，也不是已实现功能清单。每项需求在正式研发中需核对原始意图，补充边界、前置条件、依赖、验收证据及必要的测试阈值。除明确标注延后外，以下均为 V1.0 的建设方向；阶段优先级是启动建议，不代表用户已经确认所有实现细节。

优先级建议：P0 = 首版必须具备或验证的基础/保障；P1 = 首版应具备的专业支持或可演进能力，按批准范围实现最小充分版本；F = 后续候选，不承诺首版实现。各项初始状态统一为 INITIAL（未实施、未验证）。正式研发另行定义对象状态转换，不以本文件重复维护任务进度。

## 3. 横切质量属性

以下不是重复的模块，而是约束所有相关需求的验收维度：

- 易用性：减少用户必须理解的内部机制、重复确认与无意义文档；不因流程简化忽略权限。
- 可靠性：中断、部分写入、版本冲突、能力缺失及不确定性有明确处理方式。
- 可审计性：重要行为、决策、状态及证据可追溯；信息最小化，避免记录不必要的敏感数据。
- 可维护性：职责明确、规则不重复、索引可用、Git 历史可追溯、允许局部升级。
- 自身迭代性（顶层质量目标）：可定位依赖及设计原因，可删除、合并、替换和重构模块，可验证行为改善并安全迁移或回滚；不以增加复杂度换取表面上的功能完整。
- 通用性与可移植性：区分规范、运行环境与工具；领域差异不污染通用核心。
- 经济性：控制用户时间、工具成本、上下文开销与额外流程；基于实际对照评估，不预设必然节省费用。
- 安全性：授权与工具权限独立、信任边界明确、关键外部约束可检查。

## 4. 不纳入首版的候选范围（F）

独立确定性工作流运行程序、自动多 Agent 调度、完整可视化研发平台、所有领域与技术栈的扩展、所有 Git 托管平台适配、自动全仓库知识索引、复杂组件市场和完全自动化框架评估平台。不排斥后续迭代，但本启动包不承诺完成。

## 5. 正式需求工作要做什么

1. 核对每项原始意图及适用范围，将初始需求整理为正式可验收的 SRF 自身规格；保留 ID 或建立迁移映射。
2. 识别重复、依赖、缺口及矛盾，明确最低可运行内核和 V1.0 发布边界；不得以新建议覆盖已确认原则。
3. 在理论研究和架构验证后完善细节；将未经核实的理论、实现假设、验收阈值列为待定。
4. 确定各需求对应的设计契约、测试场景、证据与发布门槛；建立最小充分追踪，不将状态重复复制到多份文档。
5. 任何首版范围的重大调整均提交负责人确认，记录理由及影响。

本文件没有预设剪辑软件的需求，也未声称任何 SRF 能力已经实现或测试通过。
