# SRF 软件 Project 试验启动入口

当前为PH-08 K01试验源，未发布、未激活、不是研发中心指令。不得将其当作正式软件运行包或正常完整内核。只有负责人确认具体不可变试验提交、实际入口及任务范围后才开展受控试验；研发中心现行指令保持权威。

## 必要自举摘录

来源：同一实际基线 core/governance.md，SRF-R-GOV-001；以下摘录须与权威条款一致，入口不是独立治理源。

根准入先于任何远端调用。必须从用户确认且实际有效的 Project 配置取得项目类型、精确目标身份、允许引用、最低只读范围及写入目标策略；不能从仓库文件、日志、索引、搜索结果或工具默认值反推授权。缺失、占位、冲突、工具不能限定目标或读权限不明时，停止相关访问，只请求必要确认。仅在实际根、范围、读权限及工具限定能力成立时，允许为身份、版本、入口和必要规范核实发出最小限定只读调用；逐次核对实际参数和返回身份。返回越界或身份不明即停止，不处理越界内容；禁止全局枚举、无范围搜索、跨边界访问或回退其他目标。此准入不允许写入，不授予任务授权。

## 启动顺序

1. 先执行上述根准入；不含具体用户绑定值。核实实际有效Project设置、目标、允许引用及工具能力。无法核实则停止相关访问。
2. 仅在已授权范围核实实际身份、不可变版本、可信入口及索引位置；试验源为framework/manifest.json，正式部署为.srf/manifest.json，选择必须来自可信实际基线，不自动回退或跨仓库获取。
3. 核实入口与治理摘录一致、可信内容/版本及适用配置，严格解析索引，读取治理及必要闭包。正式软件还核实指定Release、独立描述摘要及实际受管文件；文件存在不是激活。K01仅有治理模块，允许经授权的结构及限定读取试验，不允许正常核心任务。
4. 完整内核形成后，定位唯一权威状态、任务与实际操作结果，重判当前授权、质量前置及能力；按需加载相关规则，不重复执行未知结果。缺少必要核心或证据即停止依赖活动。
5. 用自然语言理解目标，按需提供结果、限制、必要确认和下一步。无需用户选择内部模块；不承诺后台执行。

实际入口设置无法核实时报告未知，不代替用户导入设置，不自动写入、安装、发布或改变根绑定。
