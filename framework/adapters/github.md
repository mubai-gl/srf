# SRF GitHub 适配

## CONTRACT
Module: srf.github

- 职责：SYS-07的GitHub具体适配，落实统一执行及仓库操作协议；不改变通用核心授权或质量规则，不硬编码软件项目身份。
- 触发：已授权GitHub读取、变更、差异核验、异常恢复；分支、PR、发布仅在实际项目策略及专项授权允许时。
- 输入：有效根、显式仓库和允许引用、统一请求、基础HEAD/树/文件SHA、实际接口及保护条件。
- 输出：实际调用及目标、真实对象/分支/差异证据、子项结果、限制及恢复定位。
- 前置：索引声明的治理规范前置；运行时消费统一执行、授权、事实及工程治理的适用结论，不能因适配模块可加载即获执行授权。K03仅部分核心。
- 完成与失败：实际目标与预期差异、内容及保护范围核实；异常按EXE规则停止/核实，能力不足交接；不宣称CAS或系统隔离未经验证。
- 关联：REQ-014/024/034–036/049/051；J15/J16/J37；F24–F29/F39。实际接口声明和正常路径、负向测试分别记录。

### SRF-R-GIT-001 | MUST

从用户确认的有效根取得实际仓库及允许引用策略，不从默认分支、仓库正文、搜索或工具结果反推目标；每次调用前核对实际仓库、引用及路径，返回后核实身份。禁止全局枚举、无范围搜索、跨仓库、重定向或子模块绕过；实际无法限定则不调用。写显式目标branch；Git对象准备明确所属仓库及本次授权目标分支，最终引用更新显式分支。研发中心遵其独立单仓库main及首发前无分支/PR策略；软件项目按自己的有效配置，不从本适配获得例外。

### SRF-R-GIT-002 | MUST

预检真实仓库、工作分支、授权、能力/平台保护、HEAD及基树；同一已核实不可变提交读取相关完整文件、当前blob SHA及必要引用。新增核实不存在（完整限定查询）；修改保留无关内容；删除核实明确授权路径及引用影响；移动为源/目标及引用修复的逻辑变更，先核实目标不存在及冲突。拒绝无边界递归删除，保护模式、类型及其他路径。路径合法性、实际链接、二进制/LFS、编码、大小、分页/截断、速率及工作流权限分项判断，文本接口不等于无损二进制能力。

### SRF-R-GIT-003 | MUST

准备完整逻辑差异、保护集、验证及恢复定位；写前再次核实基线与前置。独立文件可用实际Contents接口（显式branch，新增存在性条件，修改/删除当前blob SHA）；不得并行更新/删除同一路径。依赖性多文件优先一次逻辑提交：从基树生成候选树，完整比较路径、类型、模式及无关对象；创建提交并核实实际树与预期父提交；再次核实目标HEAD，按适用条件非强制更新明确分支。创建树/提交不是分支更新成功。实际返回仅SHA时须限定读取核实对象，不能只信名称或返回值。

### SRF-R-GIT-004 | MUST

HEAD预读只能发现已观察变化；blob条件仅保护具体文件，新增不存在条件不保护全树；非快进保护不等于精确预期旧HEAD比较。严格CAS需服务端原子比较更新的真实语义及足够证据；expected_sha字段或正常成功不能证明。禁止force:true及默认强推/重写历史；需要严格保障而未证实时阻塞并交接。允许的普通低风险操作仍须实际满足适用条件并明确残余竞态；不通过一般授权豁免保护。批量能力不足仅在完整准备、每步授权/前置、中间状态风险可接受且可恢复时串行，每步核实新基线及结果；中间态不可接受则交接，不称串行为原子。

### SRF-R-GIT-005 | MUST

回读实际目标分支HEAD、提交父节点及树、完整真实差异、相关内容及SHA、无关路径与模式、必要CI；分页或截断时补足合法比较，不能仅凭统计。HEAD改变时核实预期提交是否进入目标历史及后续差异，区分历史成功和当前目标；相同内容或HEAD不等于预期均不能单独证明自己执行成功/未执行。未知、部分、意外差异及并发按EXE-006核实子项，停止依赖动作，不盲重试或覆盖他人内容。补偿需适用授权及实际基线；不擅自清理未引用Git对象。状态写入沿FCT-010。

### SRF-R-GIT-006 | REFERENCE

当前连接器接口映射为可替换参考，调用前以真实工具定义核实，不是永久公共API：
- get_repo(repository_full_name)；fetch限定仓库内branches/明确分支、git/trees/已核实SHA、git/commits/已核实SHA；核对返回URL、对象身份、完整性。
- fetch_file(repository_full_name,path,ref)；修改前完整读取，核对display_url、sha、encoding及git_lfs_pointer。
- create_file/update_file/delete_file显式repository_full_name、path、branch；新增核实不存在，修改/删除传当前sha；核对返回commit_sha及适用content_sha。
- create_tree(repository_full_name,base_tree_sha,tree_elements)；create_commit(repository_full_name,tree_sha,parent_sha,message)；update_ref(repository_full_name,branch_name,sha,expected_sha,force:false)；分别核实树、父节点、实际引用。expected_sha声明拒绝不匹配，严格原子CAS未由正常路径证明。
- compare_commits(repo_full_name,base,head)或限定fetch compare/已核实base...head；检查身份、完整性、too_large及实际文件/模式/内容。
- Actions、构建、测试、发布、分支/PR仅按实际能力与授权启用；查询不等于执行，触发/排队/运行/结果分别核实。实际证据与限制复用权威研发状态及历史，不在适配器维护固定能力矩阵。
